## Implemented behavior and limits

### Sessions, frames, spaces and legacy rendering

[Session initialization](https://www.w3.org/TR/2026/CRD-webxr-20260609/#dom-xrsystem-requestsession), [frames](https://www.w3.org/TR/2026/CRD-webxr-20260609/#xrframe-interface), and [reference spaces](https://www.w3.org/TR/2026/CRD-webxr-20260609/#xrreferencespace-interface) guide the focused assertions in [conformance.ts](../tests/conformance.ts). Both system entry points wait for asynchronous configuration. Immersive requests require transient user activation, exclude concurrent/pending immersive sessions, and release that exclusion after end or failed negotiation. Inline sessions are hidden while immersive presentation is active. Document visibility produces `visibilitychange`; showing the document keeps inline sessions hidden until immersive presentation ends. No synthetic tracking loss or `visible-blurred` state is generated.

Animation callbacks run in registration order with cancellation, one active frame and one monotonic desktop RAF timestamp. Event frames permit poses but reject `getViewerPose`. Stored frames and hit/depth results reject access after their callback. Spaces, sources, probes, layers and views have session/frame ownership checks. Ending a session stops its loop, drops callbacks/inputs, deactivates hit sources, deletes anchors, releases layer GL resources, and restores canvas state. A profile/mode change ends active presentation before replacing the device. [Session shutdown](https://www.w3.org/TR/2026/CRD-webxr-20260609/#session-shutdown) queues the public `end` event and promise resolution; ending inside an input handler preserves the identity for the current action's paired events, then stops further input/frame processing.

`XRRigidTransform` validates finite components, point `w`, and nonzero normalizable quaternions, and caches the inverse. Offset spaces compose in world coordinates, including when used as either argument of `getPose`. The room floor is world Y=0; local eye height is 1.6 m. `emulatedPosition` is true, velocities are unavailable. Quest views have left/right eye transforms and positive nonoverlapping viewports in both preview settings. Disabling stereo selects the left image for presentation without removing an exposed API region. The phone follows the virtual tablet and remains monoscopic. Immersive legacy rendering uses owned framebuffers; inline rendering uses the default framebuffer. See Issue #33 below for fixed storage, presentation and DPR/resize policy.

### Reference-space request contracts (Issues #39 and #41)

[Request behavior, retained ended-session correction, pinned WPT adaptations and focused commands](webxr-reference-space.md) describe required enum conversion and receiver validation, fresh viewer/bounded identities, session-realm allocation through borrowed methods, and task settlement. Shutdown rejects pending granted and ungranted requests with `InvalidStateError`, releases their records and guards queued allocation/rejection and delayed adapter continuations. Already settled outcomes and other sessions remain unchanged. Requests created after shutdown (including after coercion itself shuts down the session) still follow granted support without restarting presentation; unrelated frame/session liveness checks remain in force. The [Issue #41 validation record](webxr-reference-space-shutdown-validation-2026-10-24.json) corrects the pending-at-end assumption in the retained [historical Issue #39 report](webxr-reference-space-validation-2026-10-24.json) and records Chromium and Firefox execution for all three immersive configurations and inline on both device profiles. This preserves the viewer-only inline policy and enables no feature.

### Existing XR event contracts (Issue #31)

`ondevicechange` and the nine existing session properties (`onend`, `onvisibilitychange`, `oninputsourceschange`, select/start/end and squeeze/start/end) are enumerable prototype accessors. Each active property occupies one native listener slot. Replacing its value preserves registration order; assigning null or a primitive removes it, and reactivation registers at the current end. Non-callable objects retain identity and reserve the slot without invoking `handleEvent`. Direct `dispatchEvent()` and runtime delivery share receiver/target/currentTarget/phase, immediate propagation and cancellation. A literal false return cancels cancelable events. Native dispatch reports a thrown callback once and continues later listeners; input frame deactivation still runs in `finally`.

`XRSessionEvent`, `XRInputSourceEvent` and `XRInputSourcesChangeEvent` directly inherit from `Event`. Both constructor arguments are required; type uses DOMString conversion. Dictionaries read inherited `bubbles`, `cancelable`, `composed` followed by their own members once in lexicographic order. Missing/undefined required members, null or forged/proxy interfaces and invalid/noniterable sequences throw synchronous `TypeError`; getter and iterator exceptions propagate unchanged. Declared data attributes are branded readonly prototype accessors. Change arrays are frozen independent snapshots retaining order, duplicates and source identities; caller arrays and sources remain mutable. Sessions and input sources now join frames/spaces/joints in the private shared allocation registry, accepting genuine separately injected same-origin iframe and opener-linked popup values. Constructor validation adds no session ownership, matching-session, active-frame or live-session restriction.

Synthetic construction/dispatch does not activate frames, mutate live inputs or end sessions. Real Quest select/squeeze and Android transient select still run with active event frames through listeners and properties: pose reads work, event-frame viewer poses reject, and retained frames reject afterward, including after exceptions. Shutdown cleans resources before one task-queued public end event. These contracts add no feature descriptor and do not complete missing `XRReferenceSpaceEvent`/`XRVisibilityMaskChangeEvent`, native permission enforcement or broader WebIDL work.

Borrowed event getters recognize genuine events across separately injected same-origin iframe and opener-linked popup realms, preserving all six attribute identities and rejecting proxies, prototype forgeries and other event interfaces. Session handler accessors share one value and native listener per target/type across injections; borrowing an accessor preserves callback/object identity, replacement position, single delivery and null removal.

The fixed [Device CRD §12](https://www.w3.org/TR/2026/CRD-webxr-20260609/#events), [HTML b342939](https://github.com/whatwg/html/blob/b342939ba3b7e40041655fb926f6e41b54fe47ef/source) event-handler IDL/activation/processing algorithms and [WebIDL 622910c](https://github.com/whatwg/webidl/blob/622910c67c724e362f71e8255a0380bade261acb/index.bs) DOMString, dictionary, interface, sequence and LegacyTreatNonObjectAsNull algorithms define this scope. No Issue requirement correction was needed.

### Session-request argument snapshots (Issue #25)

Both XRSystem methods convert mode once to the enum before other work. `requestSession()` then snapshots the scoped dictionary members in WebIDL order: `depthSensing`, `domOverlay`, `optionalFeatures`, `requiredFeatures`. Omitted, undefined, null and function dictionaries work; other primitives reject. Conversion reads inherited/nonenumerable properties once without enumeration or unknown-property access. Feature sequences accept object iterables (including Sets and generators) and convert each DOMString once. Invalid dictionaries, sequences, enums and Element brands reject with `TypeError` through Promises; getter/iterator/conversion exceptions retain their original reason.

`document.all` is retained as an Object for dictionary and iterable sequence conversion despite its legacy loose-null equality and `typeof` behavior. Browser regressions check ordered dictionary reads, required-feature rejection, and optional-feature conversion/omission on both profiles.

Depth initialization converts `dataFormatPreference`, `depthTypeRequest`, `matchDepthView`, `usagePreference` in that order, including required sequences even without a requested depth descriptor. `matchDepthView` defaults to true; the simulator always returns view-aligned depth, including when false permits other behavior. `depthTypeRequest` is converted but may be ignored as allowed by the pinned draft; existing smooth virtual CPU depth and supported format selection/defaults remain. Missing/incompatible required depth rejects; incompatible optional depth is omitted. No new feature or GPU path is added.

Nullable DOM Overlay retains its original Element reference, including genuine same-origin cross-realm Elements. Presentation still checks live eligibility and opt-in preview restrictions; caller reassignment cannot substitute another root. Conversion completes before activation/concurrency checks and before awaiting configuration, so failure allocates no session/presentation resources or pending immersive ownership. Existing end/failure restoration and ownership behavior remain.

The pinned [Device CRD](https://www.w3.org/TR/2026/CRD-webxr-20260609/), [WebIDL revision 622910c](https://raw.githubusercontent.com/whatwg/webidl/622910c67c724e362f71e8255a0380bade261acb/index.bs) (`js-dictionary`, `js-enumeration`, `js-sequence` and `es-operations` algorithms), [Depth WD](https://www.w3.org/TR/2026/WD-webxr-depth-sensing-1-20260825/#session-configuration), and [DOM Overlay WD](https://www.w3.org/TR/2024/WD-webxr-dom-overlays-1-20240924/#initialization) define this bounded implementation. Full WebIDL/native conformance and the other unfinished modules in this inventory remain outside this change.

[Focused conversion and delayed-init assertions](../tests/session-request.ts) run through [conformance.ts](../tests/conformance.ts) and the existing Chromium extension runner, with no-gesture cases in [fixture.ts](../tests/fixture.ts). Deferred tests instantiate the packaged `CustomWebXRPolyfill` after draining the extension's automatic configuration, then dispatch the real `webxr-device-init` event with the repository profile configuration. They use real emulator devices and presentations, with no fake-device substitution. This controls delivery without depending on storage timing or changing production initialization. Inline runs on both profiles; immersive runs cover Quest VR/MR and Android AR, including frames, depth format retention, original-root preview and restoration, live eligibility failure and ownership recovery.

WPT reconciliation: the [pinned missing-mode test](https://github.com/web-platform-tests/wpt/blob/e1859580b5fcf74940a18d2f783296b4961035e3/webxr/xrDevice_requestSession_no_mode.https.html) uses `assert_throws_js(TypeError)` around `requestSession()`. That original synchronous-throw assumption conflicts with the pinned WebIDL operation algorithm (`#es-operations`), which maps conversion exceptions in Promise-returning operations to rejected Promises. The adapted focused assertion checks a returned Promise rejected with `TypeError`, preserving the reason and the Issue's requirement. Unknown-required, optional-feature omission and no-gesture assertions also run against actual extension sessions rather than WPT fake devices/activation. ### Numeric render-state updates (Issue #23)

`updateRenderState()`, `undefined`, `null`, `{}` and dictionaries containing only undefined numeric members leave the active and pending values unchanged on live sessions. Invalid primitive dictionaries throw `TypeError`. The supported dictionary members are snapshotted in WebIDL order (`baseLayer`, `depthFar`, `depthNear`, `inlineVerticalFieldOfView`, `layers`); inherited/nonenumerable members are included, explicit undefined is omitted, and unknown properties are never read. Numeric members use finite WebIDL `double` conversion: numeric strings/objects and null (zero) work; NaN, infinity, Symbol and BigInt conversions fail. Getter/conversion exceptions propagate before session algorithms, including on ended sessions. Rejection commits no numeric values. Ended sessions still reject converted empty input; immersive sessions reject any supplied converted FOV, including null converted to zero. Existing layer feature negotiation, ownership and destruction/transition behavior are preserved.

Successive partial updates merge into pending state. Activation clamps `depthNear` to at least **0.01 meters**, `depthFar` to at most **10,000 meters**, and inline FOV to **[0.01, 3.13] radians**, before projection construction. These are emulator-selected limits for both profiles. Near has no maximum and far has no minimum; negative far and far below near are accepted without adding an ordering restriction. Such configurations need not produce useful visible geometry. Updates during a callback leave the active values and all views' projections consistent for that frame; subsequent rendered frames use the update. Pending numeric state can activate before a presentation layer is selected. Numeric-only changes retain the selected base/composition layers and pending layer removal/transitions.

The fixed [Device CRD, 9 June 2026](https://www.w3.org/TR/2026/CRD-webxr-20260609/#dom-xrsession-updaterenderstate), [WebIDL revision 622910c](https://raw.githubusercontent.com/whatwg/webidl/622910c67c724e362f71e8255a0380bade261acb/index.bs) (dictionary and double conversion), and [Layers WD, 11 August 2026, §11.2](https://www.w3.org/TR/2026/WD-webxrlayers-1-20260811/#updaterenderstate-changes) define this bounded path. This does not claim complete render-state/WebIDL conformance: cross-update render-state object identity and additional render-state members remain outside Issue #23; session-request conversion is now implemented separately in Issue #25.

[Focused browser assertions](../tests/render-state.ts), invoked by [conformance.ts](../tests/conformance.ts), cover inline on both profiles and all three immersive profile/mode combinations. They render a triangle using the actual view projection, verify application and presentation pixels before/after updates through legacy WebGL and immersive WebGL2 projection layers without requesting `layers`, and check every view's changed projection and activation-time limits. Inline WebGL2 uses the legacy base layer because the binding requires an immersive session. With Quest stereo output disabled, the legacy right-eye viewport has zero width: pixels are checked on the enabled output, and both views' projections are checked. Existing Three.js depth-enabled rendering and feature-enabled layers/destruction checks remain. Three.js 0.186.1's caught depth-disabled `DepthTexture` client error demonstrates initialization only, never successful rendering.

Applicable cases from the [pinned WPT render-state test](https://github.com/web-platform-tests/wpt/blob/e1859580b5fcf74940a18d2f783296b4961035e3/webxr/render_state_update.https.html) are represented by equivalent focused assertions (ended/empty sessions, foreign base layer, immersive FOV rejection, deferred clip updates). They use real emulator sessions and the existing extension runner instead of WPT fake-device setup. The pinned test itself is **not** added to or executed by `test:wpt`, whose five-file selection is unchanged. Its expectation that both negative clip distances become exactly zero conflicts with this Device baseline's near-minimum/far-maximum algorithm; our assertions deliberately expect 0.01 for negative near and retain negative far, and separately test the far maximum. No correction to Issue #23's requirements was needed.

### Environmental geometry and navigation

Request `plane-detection` and/or `mesh-detection` for Quest MR or Android AR. The packaged hall's nondegenerate triangles become tracked patches; the decorative sky is excluded consistently from detection, Hit Test and depth. These are useful renderable surface patches, **not** recognized whole walls, merged polygons, scanned meshes or physical sensors. `semanticLabel` is null. Plane polygons are frozen point arrays with Y=0 in plane space; mesh data uses Float32 vertices and Uint32 triangle indices. Both origins are triangle centroids, with +Y along the world face normal. Orientation is horizontal/vertical within a small numerical tolerance, otherwise null.

Objects and spaces retain identity while their source mesh/triangle is present. Each active frame gets read-only membership snapshots. Shape/orientation changes update `lastChangedTime`; pure pose/viewer changes do not. Room removal drops tracking (old spaces return null), reacquisition creates fresh objects, and session end clears identities. Frame getters require an active frame; disabled detection returns empty sets. Foreign-session spaces reject through `getPose`. Surface spaces work with offset reference spaces and anchor creation. `initiateRoomCapture()` follows the draft's automatic-capture branch: it resolves once with plane detection enabled and rejects repeated calls with `InvalidStateError`; it never triggers a camera or capture UI.

`unbounded` must be requested explicitly. It shares the fixed local origin at Y=1.6 m, supports offset composition and arbitrary virtual viewer translation without clamping/recentering, and does not imply endless room geometry or physical tracking.

### Bounded-floor virtual play area (Issue #21)

The [bounded reference-space support and geometry algorithms](https://www.w3.org/TR/2026/CRD-webxr-20260609/#xrboundedreferencespace-interface) guide this deterministic simulation. Quest VR, Quest MR and Android AR have a known virtual floor and an explicitly authored boundary; both required and optional `bounded-floor` negotiation enable it. It is never implicitly enabled. Inline requests reject required or omit optional, as do configurations that do not declare this feature. Mode availability continues to follow the selected panel mode. No empty bounded space is fabricated for an unsupported request.

The [authored polygon](../src/polyfill/virtual-play-area.ts) is a 2 × 2 m rectangle centered on world `(0, 0, 0)` in `assets/hall_empty.glb`: `(-1, 0, -1) → (1, 0, -1) → (1, 0, 1) → (-1, 0, 1)`, closed back to the first vertex. These are meters, native Y=0 and W=1, clockwise viewed from +Y toward -Y. Its finite integer coordinates also fall on a 5 cm grid. The polygon is intentionally chosen as the usable central floor region, not inferred from collision triangles or the hall's outer perimeter. [Asset validation](../tests/play-area.ts) clips the hall's six floor triangles to verify complete 4 m² coverage and checks that no non-sky room triangle enters the rectangle's prism from Y=0.01 to Y=1.8 m. Replacing the asset requires revalidating/authoring a matching boundary; otherwise remove `bounded-floor` from the profile feature lists until that work is complete.

```js
const session = await navigator.xr.requestSession('immersive-ar', {
  requiredFeatures: ['bounded-floor']
});
const bounds = await session.requestReferenceSpace('bounded-floor');
// bounds instanceof XRBoundedReferenceSpace; extends XRReferenceSpace.
for (const point of bounds.boundsGeometry) console.log(point.x, point.y, point.z);
```

Each request creates an independent bounded space with a stable frozen array of frozen `DOMPointReadOnly` vertices. `getOffsetReferenceSpace()` retains the subclass, uses the inverse cumulative origin offset exactly once and agrees with `getPose`/`getViewerPose`. Native Y=0 is shared with `local-floor`; offset translation/pitch may produce effective vertices with nonzero Y. Source bounds and previous offset spaces remain unchanged. Viewer motion never clamps or recenters the region. Ending a session leaves immutable geometry snapshots readable, while new reference-space requests follow granted support even after end and frame pose access rejects; spaces from another session are rejected. New sessions/profiles use the same authored region.

This is **developer testing only, not real guardian/chaperone safety limits**. It uses no physical floor, cameras or guardian data, requests no additional extension permissions, and needs no experimental WebXR browser flag. The [floor-outline demo](../examples/bounded-floor.html) visualizes returned vertices strictly as an emulator debugging aid. Serve the repository root over localhost after installing dependencies; its Three.js import uses local `node_modules`. The browser suite imports the same [demo renderer](../examples/bounded-floor.js), checks visible green pixels and exact agreement between outline vertices and runtime geometry on Quest VR/MR and Android AR. Screenshots are saved under `test-results/bounded-floor-*.png`. Representative captures are committed for [Quest VR](validation/issue-21/quest-vr.png), [Quest MR on the hall floor](validation/issue-21/quest-mr.png), and the [Android application framebuffer](validation/issue-21/android-ar-application.png).

### Hit tests and DOM interaction

[Hit test source/results algorithms](https://www.w3.org/TR/2025/WD-webxr-hit-test-1-20251211/#hit-test-source) drive feature, lifecycle, cancellation and error checks. The packaged room is the sensed environment. Plane and mesh queries intersect its polygon surfaces, return nearest-first intersections, apply `offsetRay` in the source's effective space and retain the transformed face normal as pose +Y. Point-cloud queries reject because there is no point cloud. Repeated cancellation throws `InvalidStateError`. A cancelled source remains in an already-created frame's snapshot, but is absent from subsequent frames. A transient query matches `generic-touchscreen` exactly and produces results only for the associated active screen source; Quest has no transient touchscreen.

[Issue #17](https://github.com/takahirox/WebXR-emulator-extension/issues/17) introduces an explicitly opt-in **Interactive DOM Overlay Preview**, disabled by default. It deliberately has a smaller product scope than the [DOM Overlays Module](https://www.w3.org/TR/2024/WD-webxr-dom-overlays-1-20240924/). In the WebXR DevTools panel, enable the preview and select Android AR or Quest MR, then use existing application requests:

```js
await navigator.xr.requestSession('immersive-ar', {
  optionalFeatures: ['dom-overlay'],
  domOverlay: {root: document.getElementById('overlay')}
});
```

Eligible connected HTML roots in the current document's body/light tree are presented as the original live DOM in the native popover top layer, with no reparenting/copying. Android uses phone projection, falling back to a flat panel for body roots/fixed descendants (or choose **Android layout → Flat desktop panel** for small/complex UI); Quest uses one flat foreground desktop panel. Native desktop click, checkbox, keyboard/input/change, focus and scrolling work through the browser. No preview pointer is converted to an XR touch, controller pose, synthetic DOM event or `beforexrselect`. No privileged bridge or iframe/sandbox/shadow security bypass is provided. Existing non-overlay XR paths continue to work.

Required/optional `dom-overlay` requests enable the preview only with opt-in, a supported immersive AR profile/mode, popover availability and an eligible root. Enabled features include the descriptor; state is a frozen `{type: 'screen'}` retained after end. With opt-in off or an unsupported root/mode, required requests reject with `NotSupportedError`, optional requests omit with null state, and the root is untouched. Canceled/failed popover presentation restores root styles/attributes and follows the same required/optional policy. Malformed root brands reject with `TypeError` during conversion, regardless of opt-in. Inline/Quest VR, foreign-document/disconnected/SVG/document-element/embedded/replaced-control roots, shadow-tree roots, existing popovers, inert ancestors and active modal documents are declined. Changes to profile, mode or opt-in end the active session. End, removal/reparenting, pagehide and extension invalidation release resources and restore the startup style snapshot without changing app ownership.

**Standards compliance remains unfinished:** `:xr-overlay` never matches; there are no native XR UA styles/backdrop/fullscreen guarantees, world-space rays, XR-driven cross-origin forwarding restrictions, exact eye composition or full CSS/viewport emulation. Ordinary browser boundaries apply because the preview never forwards XR input into descendants. Root layout uses temporary inline styles and preview dimensions; viewport units/media queries remain desktop-based. Arbitrary custom elements, closed shadows and iframe controls are unvalidated. This is practical display/interaction support, not a standards-conformant DOM Overlay implementation. See [usage](../README.md#interactive-dom-overlay-preview-opt-in) and [implementation/validation](dom-overlay-preview.md). Administratively closed Issues #13/#15 did not complete their full standards acceptance; those gaps are preserved for future enhancement.

### Controllers, touch and hands

The [Quest Touch Plus registry profile](https://github.com/immersive-web/webxr-input-profiles/blob/main/packages/registry/profiles/meta/meta-quest-touch-plus.json) supplies `meta-quest-touch-plus`, `oculus-touch-v3`, `oculus-touch`, and generic fallbacks. Trigger/squeeze are buttons 0/1, button 2 is an inert placeholder, and joystick axes are 2/3 after the required placeholders. Each source retains one Gamepad while active, with empty `id`, index `-1`, `xr-standard` mapping and frozen per-frame axes/buttons. Removal, metadata replacement and session end permanently disconnect that exposure and retain its final sampled axes, buttons and timestamp. Later input, reconnection, restart or profile changes cannot update or reconnect it. This final-state retention is emulator policy. The existing panel supplies trigger/squeeze state; haptics are absent. Transient phone sources expose `screen`, handedness `none`, no grip/gamepad, and a fresh source identity per touch. Added-source events precede `selectstart`; `select`, `selectend` precede removal. Release-event poses retain the final tracked input transform.

Every source snapshots handedness, target-ray mode, ordered profiles and Gamepad presence. `profiles` is one frozen array per source; all public input metadata, including stable target-ray/grip/hand references and boolean `skipRendering` (`false` for current virtual inputs), is readonly. Changes to identity-defining adapter metadata replace the source and emit one `inputsourceschange` containing old and new identities after updating the live collection. Button/axis changes preserve identity. Retired same-session target-ray/grip/joint spaces return null poses; foreign-session spaces and inactive frames still throw `InvalidStateError`. No new descriptor is required. `hand-tracking` remains Quest immersive-only; additional `tracked-sources` support and virtual haptics remain follow-up work within the compatibility goal.

Correction retained from Issue #27: the earlier assessment assumed shared adapter Gamepads proved that every session must allocate universally distinct objects. The [7 July 2025 Gamepads WD](https://www.w3.org/TR/webxr-gamepads-module-1/#xrinputsource) guarantees SameObject within a source and specifies connection/frame updates; it does not explicitly mandate distinct allocation for every session. Per-source wrappers and permanent retirement are our implementation policy for coherent source lifetimes, not a universal cross-session allocation rule. The published alias identifies that publication; its dated URL was unavailable. Metadata/readonly contracts use the [9 June 2026 Device CRD](https://www.w3.org/TR/2026/CRD-webxr-20260609/#xrinputsource-interface), [WebIDL 622910c](https://raw.githubusercontent.com/whatwg/webidl/622910c67c724e362f71e8255a0380bade261acb/index.bs) and [Gamepad 81ad075](https://raw.githubusercontent.com/w3c/gamepad/81ad0752c4dd06011722b158314eef68cbc2460d/index.html). The metadata fixture also exposed pre-existing assumptions that every non-screen source has a grip and every controller Gamepad uses `xr-standard`. The Device CRD requires null grips for nontrackable gaze as well as screen sources, and the [Gamepads mapping rules](https://www.w3.org/TR/webxr-gamepads-module-1/#xr-standard-gamepad-mapping) reserve `xr-standard` for tracked-pointer sources with a grip. The replacement path applies those rules (empty mapping for the gaze fixture). Current Quest tracked-pointer and Android screen nullability remains unchanged. This corrects implementation behavior without relaxing acceptance; no Issue requirement was weakened.

When Quest sessions explicitly enable [hand input](https://www.w3.org/TR/2024/WD-webxr-hand-input-1-20240605/#xrhand-interface), both input sources use `generic-hand-select` with 25 ordered joints. The controller pose moves the hand; the panel trigger curls its fingers. Joint spaces, radii, poses and bulk pose/radius fills are implemented. Without that feature controllers have `hand === null`; the phone cannot negotiate it. This is a reproducible skeleton, not optical tracking, and does not simulate hand/controller switching within an active session.

### Bulk poses and joint radii (Issue #29)

`fillPoses()` and `fillJointRadii()` follow the pinned [Hands WD §4.1](https://www.w3.org/TR/2024/WD-webxr-hand-input-1-20240605/#xrframe), [Device CRD pose algorithms](https://www.w3.org/TR/2026/CRD-webxr-20260609/#xrspace-interface), and [WebIDL revision 622910c](https://raw.githubusercontent.com/whatwg/webidl/622910c67c724e362f71e8255a0380bade261acb/index.bs) (`es-operations`, `js-interface`, `js-sequence`, `create-sequence-from-iterable`, `js-buffer-source-types`). The receiver and required argument count are checked first. Sequences consume the iterator once, capturing `next` once and checking each interface before advancing; conversion exceptions propagate synchronously. Base-space and genuine Float32Array conversion finish before the frame algorithm. Prototypes/tags cannot forge space, joint, frame or output brands; output arrays work across realms. Shared and resizable backing buffers are rejected because neither `[AllowShared]` nor `[AllowResizable]` is declared. Detached fixed buffers retain their IDL brand but offer zero usable capacity: empty fills succeed, nonempty fills reject for insufficient capacity.

Same-origin frame and popup injections share constructor allocation brands for frames, spaces and joints through accessible parent/opener links. Registry lookup tracks visited windows to terminate even when opener links form cycles. Borrowing either bulk method across these realms accepts genuine receivers and interfaces; foreign-session spaces, bases and joints then reach ownership validation and produce `InvalidStateError`. Prototype forgeries and proxies still fail conversion with `TypeError`. Brand storage is private, with frozen shared constructors and read-only membership checks; the public instance prototype chains retain their own realm.

After conversion, the methods check active/live frame state, every input's ownership, and the pose base's ownership (including empty sequences), then capacity, before output writes. Foreign ownership and inactive frames throw `InvalidStateError`; insufficient capacity throws `TypeError`. Exact and oversized arrays/subarrays retain their offsets, tails and ownership. Writes do not call replaceable public `set`/`fill` or trust shadowed `length`/`buffer` properties. Matrices follow input order; radii use meters. Unavailable matrix entries receive 16 NaNs, unavailable radii receive NaN, and either method returns false when any requested entry is unavailable while populating valid entries. Radius validity uses native hand tracking independently of any base. The deterministic skeleton has whole-hand tracking availability and agrees with individual `getPose()`/`getJointPose()` reads. Removed joints stay unavailable after source reacquisition; new sources get new hands, and surviving hands keep joint identities.

The exact-length radius-buffer behavior in Chromium source is **not** the acceptance contract: the pinned Hands algorithm rejects only insufficient capacity, so oversized radius buffers are deliberately accepted. This reconciles the already-recorded research discrepancy in Issue #29; no additional Issue requirement was corrected or relaxed. General-space `fillPoses()` remains an emulator compatibility policy for Android AR and inline. Articulated hands remain restricted to explicitly enabled Quest VR/MR `hand-tracking`; Android and inline hands remain unavailable. Active input-event frames support the bulk methods, while retained event/animation frames and shutdown sessions reject them.

[Focused coverage](../tests/bulk-frame.ts) is integrated into `conformance.ts` and the existing browser runner. It tests conversion precedence, one-shot iterables, empty input, mixed availability, duplicate/order/offset handling, caller reuse, foreign ownership with short capacity, sentinel preservation, inactive frames, shutdown and real adapter input events on Quest and Android. A controlled fixture temporarily removes one native gamepad slot during synchronous reads after the real adapter sampled the frame, then restores its property descriptor before the next tick; all 25 joints lose/recover tracking with stable source identities. Adapter source deactivation/reactivation across subsequent frames covers permanent retirement, reacquisition and survivor identity. All adapter state and fixture objects are restored/removed in `finally` blocks. Ordinary unavailable-space/base tests use an internal null matrix provider. No production testing API was introduced.

The ordinary smoke page cannot expose SharedArrayBuffer without cross-origin isolation; its per-profile reports explicitly record those skips. A separate COOP/COEP fixture in the same runner exercises same/cross-realm shared Float32Arrays and, when available, fixed and length-tracking views of growable SharedArrayBuffers, including conversion before inactive-frame errors. Resizable fixed/length-tracking, cross-realm and out-of-bounds views and detached buffers are exercised in the normal profile suites.

WPT attribution: the retained-frame InvalidStateError assertion is adapted and extended to bulk methods from [`xrFrame_lifetime.https.html` at e1859580](https://github.com/web-platform-tests/wpt/blob/e1859580b5fcf74940a18d2f783296b4961035e3/webxr/xrFrame_lifetime.https.html). It uses real emulator sessions instead of WPT fake devices, and viewer spaces for inline compatibility rather than requesting inline `local`. Bulk conversion, buffer, tracking and ownership assertions are original focused cases derived from the pinned specifications, not claimed upstream WPT tests. The existing five-file `test:wpt` selection is unchanged and was not rerun for this change. Full WPT/IDL, Firefox, physical-device and official-application success are not inferred from these tests. The optional Three.js hand-input loss/recovery exercise was not performed.

### Anchors, depth and light

[Anchor creation](https://immersive-web.github.io/anchors/#anchor-creation) from frames and hit results retains a world-space transform independently of viewer motion. Subsequent frames expose a read-only anchor set. Deleted anchors lose tracking; accessing their `anchorSpace` throws. Session end deletes all anchors. Persistent anchor handles/storage are explicitly unsupported (`NotSupportedError`); there is no claim of cross-session relocalization.

[Depth configuration](https://www.w3.org/TR/2026/WD-webxr-depth-sensing-1-20260825/#session-configuration) supports `cpu-optimized` with `float32`, `unsigned-short` and `luminance-alpha`. Empty preference lists select `cpu-optimized` and `float32`; nonempty lists must include a supported value; the first supported format wins. Invalid preference enums reject with `TypeError`. Required incompatible combinations reject; optional ones are omitted. Each view gets a 32×32 room raycast buffer: float32 meters (`rawValueToMeters=1`) or Uint16 millimeters (`rawValueToMeters=0.001`, including luminance-alpha with the low byte in the luminance channel), containing camera-plane depth rather than ray length. Zero denotes no geometry; no room loaded or paused sensing returns null. Depth results expose `transform` and `projectionMatrix` matching their associated view, with an identity `normDepthBufferFromNormView` for the aligned grid. Tests cover every eye on Quest MR and Android AR, including translated/rotated offset reference spaces and unchanged world-space depth samples. Data access requires the producing active frame; coordinates outside [0,1] throw `RangeError`. GPU depth is unsupported. Sixteen-bit depths outside 1–65535 mm are zero rather than wrapped or saturated. No camera or physical depth sensor is accessed.

The session's depth configuration getters throw `InvalidStateError` when depth sensing was not enabled. `pauseDepthSensing()` and `resumeDepthSensing()` require a live session and its active animation frame, otherwise throwing `InvalidStateError`; during a valid frame they throw `NotSupportedError` if the feature was not enabled. Repeated calls are idempotent, and the paused/resumed state persists across frames.

[Lighting probes](https://immersive-web.github.io/lighting-estimation/#xrsession) expose 27 SH coefficients, a normalized direction toward the renderer's white light at (-1,1,-1), and its 4π intensity, in a stable world-aligned probe space. Probes obey feature/session/frame checks. Only `srgba8` reflection format is accepted; no reflection cube map is available (`getReflectionCubeMap` returns null), so no `reflectionchange` is generated. Values describe virtual lighting, never the user's environment.

### Composition layers

[Layers binding/subimages](https://www.w3.org/TR/2026/WD-webxrlayers-1-20260811/#xrwebglbinding) provide real RGBA8 2D textures, optional DEPTH_COMPONENT24 or packed DEPTH24_STENCIL8 textures, per-eye projection subimages and mono quad subimages. The compositor draws these to the presentation canvas with quad world transforms, opacity and alpha blending, then restores application GL state. Texture size follows the drawing buffer and resources are released on destruction/end; foreign/stale views or destroyed layers reject. Both layer types honor `clearOnAccess`: the default `true` clears color/depth on the first subimage access per frame; `false` clears only newly allocated storage on first access and retains content across frames until resized. Repeated accesses, including the other projection eye, preserve writes within the frame. Consecutive-frame pixel tests exercise omitted/true/false options on Quest VR/MR and Android AR. Tests also read output pixels for projection and quad rendering, including application stencil rejection, rasterizer discard, sample coverage and sampler state, then switch back to `XRWebGLLayer`. Setting `layers` clears the pending legacy `baseLayer`, and setting `baseLayer` clears pending composition layers; applications supply only the property they are switching to.

As required by [Layers initialization](https://www.w3.org/TR/2026/WD-webxrlayers-1-20260811/#initialization), immersive sessions can create and submit a single projection layer without requesting `layers`. Quad creation and submission of multiple layers still require that feature. Creation allocates usable textures immediately, using the binding's fixed owned presentation dimensions for projection layers. Application canvas resizing does not reallocate these textures. Allocation and resizing preserve application pixel-unpack buffer and texture bindings. The browser suite renders a Three.js 0.186.1 mesh through projection layers, with and without `layers`, on all three immersive profile/mode combinations; it checks dimensions, framebuffer completeness, output pixels, and GL errors.

[Quad layers](https://www.w3.org/TR/2026/WD-webxrlayers-1-20260811/#xrquadlayer) render only their front faces, with culling evaluated per eye and application culling enable, face mode and winding restored afterward. Pixel regressions cover front/back orientations on all three profile/mode combinations and a quad visible to only one eye in stereo. Quad creation and `space` assignment reject null, non-space and foreign-session values with `TypeError`, preserving the previous space on failed assignment. Valid viewer and offset-space assignments affect composition. [Layer destruction](https://www.w3.org/TR/2026/WD-webxrlayers-1-20260811/#dom-xrcompositionlayer-destroy) immediately prevents subimage access/presentation and schedules removal from render state, preserving other pending layers, their order and pending depth/legacy-layer changes; repeated destruction does nothing.

The [projection initialization dictionary](https://www.w3.org/TR/2026/WD-webxrlayers-1-20260811/#xrprojectionlayerinit) defaults to depth textures; explicit `depthFormat: null` converts to zero and disables depth. The [quad initialization dictionary](https://www.w3.org/TR/2026/WD-webxrlayers-1-20260811/#xrlayerinit) creates no depth texture for omitted/null formats. Subimages expose `imageIndex: 0`, `motionVectorTexture: null`, and depth attachment dimensions (or null without depth). Browser regressions check both layer types with omitted, undefined, null, zero, DEPTH_COMPONENT/DEPTH_COMPONENT24 and DEPTH_STENCIL/DEPTH24_STENCIL8. Packed textures attach at DEPTH_STENCIL_ATTACHMENT, clear both aspects and preserve application front/back stencil masks and clear values; pixel probes verify zero initialization and stencil rejection. Three.js 0.186.1 with `depth: false` now creates its no-depth XR layer, but then fails in its own unconditional `DepthTexture` construction with a null format; the integration regression verifies the XR layer/subimage before ending that session and does not claim successful Three.js rendering in this configuration. Bindings sharing a session and WebGL context can submit layers together and access each other's subimages; pixel tests exercise both directions, while cross-context submission/access still reject.

Texture arrays, static/mipmapped layers, other color/depth formats, cylinder/equirect/cube/media layers, depth-based composition, and cross-context composition are explicitly unsupported. Their creation methods reject rather than returning stubs. The compositor does not claim native opaque-texture enforcement or hardware scan-out timing.

### Owned immersive XRWebGLLayer framebuffers (Issue #33)

`XRWebGLLayer` inherits `XRLayer`. Immersive layers own distinct stable WebGL framebuffers in the supplied context, with readonly framebuffer/dimension accessors. Inline layers retain `null`, current default-buffer dimensions and actual context antialiasing. No feature request, including `layers`, is required. The six initialization members undergo ordered dictionary conversion before session/context checks and allocation: alpha/antialias/depth default true, stencil/ignoreDepthValues false, framebufferScaleFactor 1. Nonfinite doubles and conversion failures throw `TypeError`; ended sessions, lost and incompatible immersive contexts throw `InvalidStateError`; allocation failures throw `OperationError` and roll back partial GL resources.

The [Device CRD 2026-06-09 §11](https://www.w3.org/TR/2026/CRD-webxr-20260609/#layers) permits a UA scaling policy. The emulator clamps finite scales to [1/16, 2], floors each recommended dimension, limits each axis to the lesser of 4096 and GL texture/renderbuffer limits, and proportionally reduces dimensions to at most 4,194,304 pixels. Minimum dimensions are 2×1 for a headset and 1×1 for a phone. Each eye receives an integer region: floor(width/2) on the left, the remainder on the right. Zero/negative/extreme finite scales remain safe. New layers snapshot current recommendations (VR window size, MR room drawing-buffer size including DPR, Android profile resolution). Existing storage and view projections stay fixed through window/DPR/application-canvas resizing; create and submit a new layer to adopt a new recommendation. The virtual display can scale the completed image to the resized window. Application canvases retain their dimensions and DOM location.

Color storage is RGB when alpha is false and RGBA otherwise. Depth requests allocate depth storage; stencil requests allocate packed depth/stencil storage, including when depth is false, as the CRD permits. `ignoreDepthValues` reports true because the compositor does not consume depth; application depth/stencil testing still works. WebGL2 selects a common supported sample count up to four for color and depth/stencil, reports antialiasing only when multisampling is allocated, and resolves before presentation. WebGL1 currently reports antialias false for immersive layers. Inline reports the default buffer's actual antialiasing.

Presentation reads completed owned storage into an independent sRGB canvas. It flips rows and converts premultiplied encoded RGB to straight-alpha ImageData; there is no extra linear-to-sRGB conversion. This honors the CRD's premultiplied interpretation independently of the default context's `premultipliedAlpha` setting. The AR room/tablet samples that canvas through the existing sRGB/linear composition path. Projection/quad composition draws into a binding-owned target, presents through the same path, and retains a separate default-output copy for compatibility observations. The CPU transfer is an emulator implementation tradeoff, not native scan-out or a GPU-performance claim. Main-thread OffscreenCanvas contexts use the same owned presentation path.

All owned buffers clear before animation callbacks with clear masks/values, scissor, texture/renderbuffer bindings, pack/unpack state and distinct WebGL2 read/draw bindings preserved. Access is available during the owning session's animation callback, including newly created or never-submitted layers; outside it, status returns FRAMEBUFFER_UNSUPPORTED and drawing/reading/clearing generates INVALID_FRAMEBUFFER_OPERATION. Ordinary attachment inspection/mutation/deletion generates INVALID_OPERATION. Core and applicable extension drawing/attachment entry points are guarded. Existing GL error flags survive. Completed display pixels remain when a callback does not render; preview changes select from the last completed stereo image. Replacement and legacy/projection/quad transitions keep reusable resources; shutdown releases all session-owned XRWebGLLayer allocations synchronously, including never-submitted layers. Context loss releases affected allocations, and rendering is skipped after loss or end inside a callback. After restoration, create a new layer; the lost layer is not resurrected.

These guards supply ordinary application behavior, not hostile-code-proof isolation. The browser harness measured a concrete bypass on Chromium: a pristine same-origin about:blank iframe's native `getFramebufferAttachmentParameter`, called with the parent context, returns its owned color texture with NO_ERROR. Normal page-realm inspection returns null/INVALID_OPERATION. This exposes the color texture to deliberate page interference and can break application rendering. Borrowing pristine mutation methods is a further possible interference path; this probe measured inspection only. This is consistent with [Mozilla's MAIN-world documentation](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/content_scripts#world), which describes page interference. Native browser support or moving the context and rendering into a separately isolated renderer are alternatives for stronger isolation; the latter would require a different application integration. No cross-origin data or native protection claim follows from these resources.

### Unsupported foveation bindings and legacy Three.js (Issue #35)

Both `XRWebGLLayer.fixedFoveation` and `XRProjectionLayer.fixedFoveation` are enumerable, configurable prototype getter/setter pairs with no own data-field shadow. Reads on genuine matching objects return `null`. Writes validate the interface allocation brand, then convert nullable `float`, before ignoring the converted value. Null/undefined succeed; numeric strings, booleans and coercible objects use ordinary number conversion once. NaN, infinities, float32 overflow, Symbols and BigInts throw `TypeError`; coercion exceptions propagate unchanged. Finite converted values outside [0,1] remain accepted no-ops. The accessors never query or modify GL resources and retain this behavior outside animation callbacks, after session end, context loss and projection destruction. Same-origin injected realms share allocation membership; borrowed accessors reject unrelated receivers, the other interface, prototype forgeries and proxies.

Receiver-validation reviews found two bypasses: shared allocation bases could brand unrelated objects through public constructor ancestry, and the subsequent injection-local fix trusted and cached arbitrary membership predicates published by page-controlled frames. Layer membership now uses private WeakSets behind frozen allocation constructors in the existing shared interface registry. These constructors initialize new layer records; there is no public brand writer or predicate-registration API. Local public constructors preserve each realm's prototypes and keep framebuffer storage local. Accessors perform only membership checks against the shared allocation records, without frame discovery or predicate caching. Direct ancestor construction, including `Reflect.construct` with `Object` or the public layer constructor as `newTarget`, cannot grant either brand. Browser regressions cover an uninjected `about:blank` iframe publishing frozen always-true predicates (even alongside a copied interface registry), both while attached and after removal. Both local and borrowed accessors reject unrelated objects, forged prototypes, proxies and the other interface before coercion; genuine retained cross-realm layers continue to work after iframe removal. Other interfaces' allocation bases are outside this fix.

This applies to Quest VR/MR and Android AR, with WebGL1/2 base layers and inline base layers on both profiles; projection rendering continues to require immersive WebGL2. There is no foveation feature descriptor. A single projection still works without `layers`; quad creation and multiple-layer submission still require it.
