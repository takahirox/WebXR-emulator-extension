# TypeScript development notes

Issue [#3](https://github.com/takahirox/WebXR-emulator-extension/issues/3) migrates all 15 maintained application JavaScript files and the Rollup build configuration together. The build configuration is now `build.ts`. No maintained JavaScript source remains. JavaScript in `src/app/three/` is unmodified vendor code; `polyfill/webxr-polyfill.js` and `dist/**/*.js` are generated browser artifacts. HTML has no maintained inline application JavaScript.

## Source and build contracts

- `src/types/contracts.ts` defines device definitions, controller capabilities, poses, emulated gamepads, custom window events, and the discriminated extension message union. Both receiving handlers and outgoing message/event producers use these contracts.
- `src/types/webxr-polyfill.d.ts` declares only the upstream internal APIs imported by this extension, including symbol-keyed session state, spaces, transforms, input sources, and the hit-test prototype extensions. It does not treat the dependency as an unrestricted `any` module. Keep these declarations aligned with the commit recorded in `package-lock.json` when changing the dependency.
- `src/types/browser.d.ts` supplies Firefox's `cloneInto`, the injected function, WebGL's compatibility extension, the custom event map, and the panel's vendor globals. The npm Three.js r111 declarations also describe the subset of vendored controls/loaders used by the panel; the panel's vendor core reports `108dev`. The actual panel and AR renderer are checked in the browser. `@types/webvr-api` supplies the legacy `VRDisplay` referenced by Three.js declarations; `@types/chrome` describes extension APIs.
- No first-party file uses `any`, `@ts-nocheck`, or a type-check exclusion. Strict null checks and implicit parameter checking are enabled, including declaration checking. DOM assertions reference elements that exist in `panel.html`; mesh assertions describe the single material passed to the r111 constructor. Session/AR assertions follow the polyfill's call order: sessions exist before frame callbacks and the AR scene is initialized before AR callbacks. The dynamic API registry uses `unknown` to install constructors by name.
- The build uses TypeScript ES2018 emission followed by Rollup. The polyfill remains UMD inside `function WebXRPolyfillInjection()`, exporting `CustomWebXRPolyfill` to the page. The other four entry points are classic IIFEs; the panel's vendor script order stays intact. There are no ES modules, dynamic imports, or asynchronous module startup in extension artifacts.
- `ConfigurationManager` is bundled into both the panel and isolated content script. Removing its separate manifest/HTML script reference preserves the execution order: its class is defined before either entry point runs. The content script still inserts the polyfill synchronously at `document_start`, then fetches device configuration and storage asynchronously. No extension APIs are bundled into the page polyfill.

Three.js stays at r111 in npm, with all panel vendor assets unchanged. `gl-matrix` resolves to 3.4.4 within the previous allowed dependency range, supplying its own declarations. Supported Rollup plugins replace the old build plugins; the bundle retains the comment cleanup step. Generated diffs include compiler formatting, current CommonJS wrappers, and the locked math dependency. Git attributes mark generated bundles and ignore their inherited vendor indentation for whitespace checks.

Strict checking exposed small existing defects: the transient hit-test source lacked its `XRRay` import; rigid-transform rays wrote to a nonexistent `_directionVec4`; AR mouse controls used the ambient `event`; `clearDepth` had an extra argument; the GLTF parse error callback was in a nonexistent fifth argument. These are corrected alongside the migration. The controls' discarded numeric multiplication is removed while preserving the existing movement delta. A null upstream input pose is returned directly before AR manipulation. Configuration fetch failures now reject the manager promise instead of leaving it pending. This change adds no new WebXR features and does not change Manifest V2.

## Validation

Executed on macOS arm64 with Node.js 24.12.0, npm 11.6.2, and desktop Chromium **131.0.6778.33** (Playwright browser build 1148) in an isolated temporary profile. No headset or external XR hardware was required.

- `npm install`: passed; the lockfile records all dependencies. npm reports one existing high-severity advisory for retained Three.js versions below r125. A Three.js security upgrade is outside this migration's compatibility scope.
- `npm run typecheck`: strict checking passes for all application sources, declarations, build tooling, and tests.
- `npm run build`: emits all five entry points. Rollup reports the upstream `XRSession` ↔ `XRFrame` circular dependency; this is a dependency warning, not a build failure. The generated polyfill keeps its injected function and UMD/global contract; manifest/HTML paths point to generated scripts.
- `npm run test:browser`: opens the real WebXR DevTools tab and loads the headset/controller assets. Changes the device to HTC Vive and disables stereo, checks storage, reloads the panel, and verifies both settings are restored. Opens immersive VR; checks page-to-panel headset/controller poses and panel-to-page reset; drags the real headset and right-controller transform gizmos and observes their XR poses; presses/releases select and squeeze through panel buttons and observes all six XR events; exits through the panel. Opens Samsung Galaxy S8+ immersive AR, loads the virtual room, obtains persistent hit-test intersections, touches the tablet with the right mouse button to obtain transient hits and select events, rotates the scene camera with the mouse, and checks its pose notification. Cancels hit-test sources, ends AR, checks rigid-transform XRRay construction, and reloads the page to confirm synchronous startup again. Checks uncaught page errors and frame errors. The DevTools panel screenshot was visually inspected for loaded assets and changed poses, and the AR screenshot for room, tablet texture, and transform controls. The run observed one each of all six VR select/squeeze events, two persistent AR intersections, and two transient intersections during touch.
- `git diff --cached --check`: passes for maintained files; generated bundles have inherited third-party indentation covered by `.gitattributes`.

The browser test deliberately selects the real registered extension tab through Chromium DevTools' internal InspectorView API because Playwright does not expose DevTools and extension OOPIF targets as normal pages. It attaches to those targets through CDP. A one-render scene callback observes the real panel camera/scene, then restores itself; the test enables the real vendor gizmos and dispatches mouse events over their handles. No extension APIs, storage, background routing, or XR implementation are mocked. Its local regression sample is authored in TypeScript and emitted in memory for the test server.

Firefox is optional and was not tested because it is not installed in this environment. Installed Google Chrome 155 was not used for the Manifest V2 run; Chromium 131 was used instead. Browser validation exercises the existing emulation, not full WebXR specification conformance. This node commits the implementation only; opening the single PR against `dev` and requesting review are downstream operations and were not performed. No post-merge verification is required by the Issue.
